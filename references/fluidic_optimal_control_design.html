Optimal Control of the Coupled Thermal-Biochemical Microfluidic System

Design and prototype for gradient-based optimal control of substrate supply and thermal management in the 1D-tube / 2D-chip system — including the extension to multiple chips sharing one supply tube. Companion document to fluidic_problem_description.md.

Numerical corrections, October 22, 2026. The current solver uses half-cell Dirichlet distances, availability-limited uptake shared by substrate, biomass and heat, a common overheating threshold of 0.10, and an exact simulation horizon. Control costs integrate applied Euler-step controls; reports show actual spatial hotspots. Existing figures and numerical optimization results below are historical outputs from the earlier solver and have not been regenerated. Regression checks: PYTHONPATH=src python -m unittest discover -s tests -v.

0. Problem Statement

Find control trajectories — tube flow velocity \(u(t)\) and inlet substrate concentration \(C_{\text{in}}(t)\) — that maximize biomass production while penalizing substrate consumption and overheating, over a horizon \(t \in [0, t_{\text{end}}]\):

\[ \min_{u(\cdot),\,C_{\text{in}}(\cdot)} \; J = -W_X\,\bar{X}(t_{\text{end}}) + W_C\!\int_0^{t_{\text{end}}}\! u\,C_{\text{in}}\,dt + W_U\!\int_0^{t_{\text{end}}}\! u^2\,dt + W_T\!\int_0^{t_{\text{end}}}\! \big[\max_{\Omega} T - T_{\text{ref}}\big]_+^2 dt \]

subject to the coupled PDE dynamics (substrate, biomass, heat in chip; advection in tube). The thermal-biochemical feedback loop makes this genuinely non-convex:

Feed \(C_{\text{in}}\)→ Growth \(\mu\)→ Heat \(Q_{\text{bio}}\)→ \(\mu(T)\) choke→ Cooling via \(u\)

1. Prototype Model (nondimensional)

State

  • Chip \(C, X, T\) on \(32\times16\) cells, domain \([0,1]\times[0,0.5]\)
  • Tube \(C, T\) on a shared 1D line (see §4 for multi-chip layout)
  • \(T\) is a deviation from the thermal optimum: \(\mu_{\max}(T)=\mu_0 e^{-(T/w_T)^2}\)

Parameters

SymbolValueMeaning
\(D_C,\,D_X\)0.05, 0.01substrate / biomass diffusivity
\(\alpha_{\text{chip}},\,\alpha_{\text{tube}}\)0.1, 0.04thermal diffusivity
\(\mu_0,\,K_s,\,\delta\)1.5, 0.10, 0.08Monod kinetics + decay
\(w_T\)0.45thermal tolerance width
\(Y_{X/C},\,Y_{Q/C}\)0.5, 1.0growth & heat yields
\(H_{\text{tube}}\)0.1tube height (flux amplifier)

Dynamics (per step, explicit Euler with \(\Delta t = 1.2\times10^{-3}\))

\[\dot{C} = D_C\nabla^2 C - \tfrac{\mu(C,T)}{Y_{X/C}}X \qquad\text{(chip)}\]
\[\dot{X} = D_X\nabla^2 X + \big(\mu(C,T)-\delta\big)X \qquad\text{(chip)}\]
\[\dot{T} = \alpha\nabla^2 T + \tfrac{Y_{Q/C}}{Y_{X/C}}\,\mu(C,T)\,X \qquad\text{(chip)}\]
\[\dot{C} = -u\,\partial_x C + D_C\partial_x^2 C - \tfrac{J_C}{H}\,,\quad \dot{T} = -u\,\partial_x T + \alpha_t\partial_x^2 T - \tfrac{J_Q}{H} \qquad\text{(tube)}\]

Initial chip: \(C_0 = 0.05\) (starved — supply matters), one Gaussian biomass seed per chip, \(T_0 = 0\). Boundary conditions as in the problem statement: Dirichlet at the interface \(y{=}0\) from the tube, no-flux on the other chip walls, Dirichlet inlet / zero-gradient outlet on the tube.

2. Discretization & Interface Coupling

Spatial operators

Second-order central differences for diffusion, first-order upwind for tube advection, implemented with ghost cells:

  • Chip walls \(x{=}0, x{=}L_x, y{=}L_y\): replicate ghost cell \(\Rightarrow\) zero-flux (Neumann).
  • Chip interface \(y{=}0\): ghost = \(2C_{\text{tube}}-C_{\text{row}_0}\), placing the Dirichlet value at the face, half a cell from row 0. The matching flux is \(J_C = -2D_C\,(C_{\text{row}_0} - C_{\text{tube}})/\Delta y\), analogously \(J_Q\) with \(\alpha\).
  • Tube inlet: diffusion ghost = \(2C_{\text{in}}-C_0\); the upwind advection stencil uses the inflow value directly. Outlet: replicate (zero gradient).

Coupling sequence per step (explicit, loose coupling)

  1. Read tube segments as Dirichlet boundary values \(C_{\text{bc}}, T_{\text{bc}}\) for every chip.
  2. Advance chip fields; the boundary-row gradients produce \(J_C, J_Q\) (per chip, shape \(M\times N_x\)).
  3. Inject \(-J/H_{\text{tube}}\) as a source term into the tube at the segment owned by each chip (a plain reshape — chips tile the tube contiguously).
  4. Advance the tube with upwind advection + diffusion + sinks.
Stability. Both rollout APIs enforce a conservative explicit positivity bound including half-cell boundary diffusion, tube advection, interface exchange, biomass diffusion and decay. The default control bounds give \(\Delta t_{\max}\approx1.76\times10^{-3}\). The driver treats --dt as a maximum and sets the actual step to horizon / steps. The prototype deliberately uses mild scale separation (\(\alpha/D_C = 2\), shallow chip) so explicit stepping stays cheap; realistic \(100{-}1000\times\) separation requires implicit diffusion (see §7).

3. Optimal Control Formulation

Control parameterization

Piecewise-constant over \(K=8\) segments, mapped to bounds through sigmoids (keeps parameters smooth and bounded, no clipping discontinuities):

\[u(t) = u_{\min} + (u_{\max}-u_{\min})\,\sigma(\theta^u_{k}), \qquad C_{\text{in}}(t) = C_{\max}\,\sigma(\theta^c_{k})\]

\(u\in[0.05,1.5]\), \(C_{\text{in}}\in[0,2]\); segment index from \(t/\Delta t_{\text{seg}}\). Initialized at the baseline constant control \((u,C_{\text{in}})=(0.5,1.0)\).

Optimizer

Full differentiable rollout through all \(2084\) Euler steps; Adam (\(\text{lr}=0.03\), 80 iterations) on \(\theta^u,\theta^c\in\mathbb{R}^8\). Gradients flow through every stencil, the Monod/thermal nonlinearities, and the interface coupling — this is the entire point of the differentiable-physics approach: no adjoint model had to be derived by hand.

Objective terms (as implemented)

TermWeightRationale
\(-W_X\,\sum_{\text{chips}}\bar{X}(t_{\text{end}})\)\(W_X=4\)reward total biomass
\(W_C\sum_k u_k C_{\text{in},k}\Delta t_{\text{seg}}\)\(W_C=0.05\)substrate pumped
\(W_U\sum_k u_k^2\Delta t_{\text{seg}}\)\(W_U=0.02\)pumping effort
\(W_T\sum_n [\max_\Omega T_n - T_{\text{ref}}]_+^2\,\Delta t\)\(W_T=3,\ T_{\text{ref}}=0.10\)hotspot overheating (spatial max, not mean)
Landscape lesson (documented from failed tunings). The first three weight/physics settings produced degenerate optima: with a pre-fed chip the optimizer simply shut off the supply (biomass was insensitive to inflow); with a tight thermal choke (\(w_T=0.25,\ Y_{Q/C}=1.5\)) heat collapse dominated every marginal gain and starvation was again optimal. The final setting — starved initial chip, mild choke, cheap substrate — yields an interior optimum where feeding, growth and cooling genuinely trade off. Always sweep constant controls first (a 4×4 grid of rollouts) to check that the objective has an interior optimum before spending iterations.

4. Multi-Chip Extension

Architecture: batched chips on a shared tube

\(M\) chips are tiled along one tube; chip \(m\) owns tube cells \([m N_x,\,(m{+}1)N_x)\). All chips advance as a batch dimension of one tensor (shape \(M\times N_y\times N_x\)) — the coupling needs only two reshape operations:

  • Downstream (tube → chips): tube.reshape(M, Nx) is every chip's Dirichlet bottom row.
  • Upstream (chips → tube): J.reshape(M·Nx) is the tube's source/sink term.

No per-chip Python loop: the same code runs \(M=1\) or \(M=50\), and the tube automatically becomes a serial resource — substrate advected past chip 0 arrives partially consumed at chip 1, so the chips compete through the shared flow.

Why this is the interesting regime

With one control pair \((u, C_{\text{in}})\) shared by all chips, the controller cannot allocate — it can only choose how hard to push the shared line. The measured outcome (§5, Figure 4): the upstream chip wins. Natural extensions, all trivially expressible in the same differentiable framework:

ExtensionControlExpected effect
Per-chip valves\(u_m(t), C_{\text{in},m}(t)\) per segmentoptimal allocation; downstream chip is feedable at lower marginal cost (substrate is already there)
Per-chip inlet temperature\(T_{\text{in},m}(t)\)active cooling of hotspots (downstream chip is the cool one today)
Receding-horizon (MPC)re-optimize every \(\Delta t_{\text{seg}}\)feedback robustness, disturbance rejection
Stochastic / RLpolicy \(\pi(\text{state})\)when the differentiable rollout is used as a differentiable simulator for policy gradient

Reading the results

  • The controller exploits the compounding advantage of early feeding: substrate converted to biomass early multiplies through exponential growth for the rest of the horizon.
  • \(u\) is not a delivery knob only — it is the thermal actuator. High \(u\) keeps the tube near \(T_{\text{in}}\), steepening the heat sink at the interface exactly when \(Q_{\text{bio}}\) peaks.
  • In the 2-chip case the optimizer accepts the downstream starvation rather than over-driving the line: with a shared control there is no way to favor chip 1 without overfeeding chip 0 into its thermal choke. This is precisely the limitation that per-chip valves would remove (§4).

5b. Individual-Based Biomass Model (IBM mode)

What changes

model_ibm.py replaces the continuum biomass field \(\partial X/\partial t = D_X\nabla^2 X + \mu X - \delta X\) with discrete agents, keeping the C/T PDEs, the tube, and the interface coupling exactly as before (the IBM swap is local to the biomass representation):

  • Fixed agent pool — tensors pos (nmax,2), mass, alive; dead slots are reused by division, so shapes never change.
  • Uptake — requested consumption \(= \mu(C_i,T_i)\,m_i/Y_{X/C}\), sampled from the fields by bilinear gather. Each agent is limited by the most depleted cell in its deposition footprint, after accounting for aggregate demand and transport. Accepted uptake drives both growth and heat.
  • Splatting — consumption and heat (\(Q=Y_{Q/C}\cdot\)consumption) are deposited onto the grid with bilinear weights (scatter_add) and become the PDE reaction terms.
  • Division — mass split at doubling (mdiv=2m_0): parent halves, child takes the other half in a free slot at the parent's position. Death below \(m_{die}\) frees the slot. Motility: reflected random walk with \(D_X\).

What keeps it differentiable

  • Division preserves instantaneous \(\sum m\) — gradients flow through masses, positions, and sampled fields within a fixed event sequence. Division changes subsequent noise-driven trajectories; hard division/death timing is not differentiated.
  • Common random numbers — motility noise is pre-generated once (fixed seed) and reused across optimizer iterations, yielding a deterministic, piecewise differentiable surrogate. Optimized schedules still need validation across independent noise seeds.
  • Scale anchoring — initial agent mass is set so total biomass matches the continuum integral; mean-field agreement verified: final biomass 0.087 (IBM) vs 0.088 (continuum), population 256 → 439 agents.
Historical division bug — fixed. The first implementation assigned the child its mass but omitted its alive flag, causing the next step to erase the child's mass. The current implementation assigns half the parent's mass to each agent and explicitly sets alive[free_idx] = True in src/fluidic_opt/model_ibm.py. The regression test test_division_preserves_mass_and_local_gradient in tests/test_fluidic_opt.py confirms that both agents are alive, division preserves total mass, and local mass gradients remain finite. 7. Framework Findings: phi.torch (phiflow 3.4)

The prototype uses PyTorch autodiff directly — the same engine phiflow's phi.torch backend drives — with hand-rolled stencils. This decision was made after empirically testing phiflow's built-ins against this problem's requirements:

Capability neededphiflow 3.4 result
Gradients through grid opsWorks — gradients flow cleanly through diffuse.explicit and even through a Dirichlet boundary value used as a control parameter (verified).
Mixed per-side BCs (Dirichlet at \(y{-}\), Neumann elsewhere)Partially — extrapolation.combine_sides({'y-': value, ...}) builds such fields, but diffuse.explicit ignores the constant (Dirichlet) value (bottom row stayed at 0.995 for a 0.5 BC after one step), and diffuse.implicit raised an assertion.
1D tube advectionFails — semi_lagrangian/mac_cormack route through torch.grid_sample, which requires ≥2 spatial dims; 1D grids crash.
Batched chipsWorks elegantly — batch dims are first-class; the multi-chip design ports directly.

Verdict. For this problem class (scalar advection–diffusion–reaction, mixed BCs, a 1D–2D interface) phiflow's ready-made physics adds little while its boundary handling is not reliable for the coupling; the custom stencils are ~60 lines and fully differentiable. phiflow remains the right tool if the chip later needs real flow (pressure-projected Navier–Stokes, moving biomass boundaries); the batched multi-chip design transfers unchanged. The stiffer, more realistic regime (large \(\alpha/D_C\)) should move diffusion to an implicit solver (Crank–Nicolson or phiflow's diffuse.implicit once BC support is confirmed), relaxing \(\Delta t\) by orders of magnitude.

7b. Framework Assessment: AgentTorch

What it is (facts as of 2026-10)

AgentTorch (MIT Media Lab, "Large Population Models") — an open-source platform for large-scale differentiable agent-based simulation: millions of GPU-batched autonomous agents, gradients through stochastic dynamics and discrete interventions, composition with LLMs and mechanistic simulators. Key metadata: 654 stars, v0.6.0 on PyPI, config-driven runner (models / populations / environments, YAML-style), showcase domain epidemiology/geospatial. License: AGPL-3.0.

Fit analysis for this project

DimensionAgentTorchOur situation
Population scale Optimized for 10⁶–10⁷ GPU-batched agents Prototype runs 10³ agents on 512-cell fields; microfluidic control studies stay at 10³–10⁵ — we never enter the regime where its infrastructure pays off
Discrete-event gradients Headline capability (relaxations of stochastic discrete behavior) Local pathwise gradients work within a fixed event sequence. Division preserves instantaneous mass but changes future trajectories; common random numbers do not differentiate hard event timing. Discrete-event gradient estimation remains future work.
Physics coupling Runner/environment abstractions geared to epidemiology-style rules; no documented path for coupling agents to a custom 2D PDE + 1D tube interface The bilinear sample/splat against our own C/T solvers is the project — we would wrap our physics in their indirection while keeping all the real work anyway
Engineering cost Config/YAML-driven API at v0.6 (research code, API churn) Current IBM is ~250 explicit, annotated lines fully under our control
License AGPL-3.0 Fine for this research repo, but viral if any derivative ever becomes a hosted tool — a real constraint to record now
Verdict: do not adopt as a dependency now. The prototype's differentiable-IBM needs are met by the hand-rolled implementation, and AgentTorch's differentiating strengths (population scale, ecosystem composition) are outside our regime. Borrow the ideas (Gumbel relaxation for division timing, straight-through event estimators) without taking the dependency.

Revisit triggers — adopt if/when

  • Scaling to full-population chips (10⁶+ cells) where GPU agent batching becomes load-bearing;
  • needing principled differentiable discrete-event estimation beyond CRN (stochastic division timing, dormancy switching);
  • moving to multi-species agent ecosystems with rich behavior rules, where their composition layer earns its keep.

If adopted: prototype on an isolated branch behind the existing simulate() contract (continuum / IBM / AgentTorch as interchangeable biomass backends) so the swap stays reversible. Check license implications separately at that point.

8. Limitations & Roadmap

  • Explicit time stepping — stiff diffusion (realistic \(\alpha/D_C\sim100\)–\(1000\)) and stiff reaction (\(\mu_0\Delta t\)) need implicit/semi-implicit treatment or subcycling.
  • Explicit interface coupling — chip and tube use the same pre-step interface flux with opposite signs, conserving exchange to roundoff. Larger transport time steps would require an implicit treatment.
  • Insulated chip walls — the Robin ambient-loss option in the problem statement is not implemented in this solver.
  • Open-loop controls — piecewise-constant schedules are open loop; MPC (§4) is the natural next step and reuses everything.
  • 2 controls only — per-chip valves, \(T_{\text{in},m}\), and spatially patterned interface fluxes are the control dimensions with the highest expected value (the 2-chip starvation result shows the headroom).
  • Parameter identification — the same differentiable rollout fits \(Y_{X/C}, Y_{Q/C}, \mu_0, K_s\) to data by replacing the control loss with a data mismatch loss; this is the DEB-relevant follow-up.
